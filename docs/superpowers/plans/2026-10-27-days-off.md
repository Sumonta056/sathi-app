# Days Off Design and Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Each buddy (Fota, Boi, Shanti, Shokti) gets weekly days and a list of single days off. On a day off that buddy is quiet, and the day never breaks its streak or lowers its report numbers.

**Architecture:** One shared Core value, `HabitDays` (weekdays that are on, plus single dates that are off), lives in every habit's prefs. Every `HabitRules` asks `HabitDays.isOn(_:)` before it picks a due day. `StreakCalculator` and `ReportBuilder` take a "counted day" check and skip days that are off. UI gets 2 shared components: a weekday row and a days-off card, used in all 4 Settings tabs.

**Tech Stack:** Swift 5.9, SwiftUI + AppKit, Swift Testing, ViewInspector 0.10.

**Spec:** this file. The "Design" part below is the spec. The conversation that produced it ran on 2026-10-26 and 2026-10-27.

## Decisions to confirm

The user confirmed all 3 calls on 2026-10-27. The user also approved per-task commits on `feature/days-off` (no push).

| # | Question | Answer (confirmed) | Why |
|---|---|---|---|
| D1 | On a day off, the user still meets the goal (for example drinks 8 glasses on a Sunday that is off). Does the day add 1 to the streak? | **Yes.** A met day always counts. An off day that is not met is skipped: it neither breaks nor adds. | Kind to the user. Doing more never hurts. |
| D2 | The user marks **today** as a day off while that buddy's reminder shows. What happens to the reminder? | **It closes at once, with no snooze event.** A running session continues. | "Quiet today" means quiet now. |

## Design

### What the user asked for (their words, 2026-10-27)

- "I want flexibility: I can choose which day off. In that case that day does not count in the streak. Like next week I want to be off on Tuesday, so Tuesday will not count."
- "Don't force Sat and Sun off by default. Every day will be open by default."
- "All buddies should take [days off]." "All buddies should have this option for choosing." Then they chose **per buddy only**: each buddy's Settings tab has its own day-off list.
- Weekly days: **yes, every buddy** gets a weekday row.
- **Single days only** for now. No date ranges.

### Goals

1. Every buddy has a weekday row. All 7 days are on by default, for every buddy, Gym included.
2. Every buddy has a list of single dates off, edited in that buddy's Settings tab.
3. On a day that is off (weekday off, or a date in the list), that buddy shows no reminder.
4. A day that is off never breaks that buddy's streak and never lowers its report numbers (see D1).
5. The menu card shows "Day off" for a buddy that is off today.

### Non-goals

- No date ranges ("3 to 7 November").
- No single day off for all buddies at once.
- No history of weekday-setting changes (see D3).
- No change to "Rest of day" or Pause. They stay as they are.

### Anti-goals

- A day off loses user data or resets other settings.
- A day off breaks a streak.
- An existing user's reminders change after the update. All new fields default to "every day on, no dates off", except the Gym weekday default (below).

### Behavior

| Item | Rule |
|---|---|
| Weekday default | All 7 on, for every buddy. |
| Gym default change | `GymPrefs.weekdays` default changes from Mon–Fri to all 7. A user who already saved Gym prefs keeps the saved Mon–Fri. Tell the user this in the final message. |
| Last weekday | The last selected weekday cannot be turned off (Schedules rule 8, now for every buddy). An empty saved set decodes as all 7. |
| Single dates | Stored as day keys `"YYYY-MM-DD"` in the Gregorian calendar of the user's time zone. Kept forever in prefs. The Settings list shows only today and later. |
| Add a date | A date picker in the buddy's tab. Allowed range: today to `Limits.daysOffMaxAhead` (365) days ahead. A date already in the list is not added twice. At most `Limits.daysOffMax` (100) future dates. |
| Remove a date | A remove button on each listed date. |
| Reminders | A habit's due time never falls on an off day. If a computed due day is off, move to the first reminder of the next on day (for each habit, its normal "first reminder of a day": Water and Meditation start time; Reading set time; Gym start + interval). |
| Today becomes off | See D2. The due time moves to the next on day (Habits rule 11 already clears the snooze when a setting moves the due time later). |
| "Show a reminder now" | Still works on an off day (Habits rule 8 stays). |
| Streak | Count back from today. Off day and goal met: +1 (D1). Off day and goal not met: skip. On day and goal not met: stop (today not met does not stop, as today). Same for "longest streak". |
| Reports | Average per day, "% of goal", and "days met" use only on days up to today. An off day that is met still counts as met. The streak calendar shows an off day with its own style ("off" cell). |
| Menu card | The pill says "Day off" when today is off for that buddy and nothing is active. |
| Older app versions | They ignore the new keys and drop them when they save prefs (same as every new field). |

### Business rules to add or change (`.claude/rules/business-logic.md`)

1. Words: add **Day off**: "A day on which one habit is quiet: a weekday that is off, or a date in that habit's days-off list."
2. Schedules rule 8 → for every habit: weekday row, default all 7, last day cannot be turned off, empty decodes as all 7.
3. New Schedules rule 10: single dates off, the 365-day and 100-date limits, day keys in the user's Gregorian calendar, kept forever.
4. New Schedules rule 11: no due time on an off day; today turned off closes the open reminder with no event (D2); a session continues.
5. Streak (Words) and Stats rules 4 and 11: D1 and the off-day calendar cell.
6. Gym row in the Schedules table: "on the selected days" instead of "work days"; default all 7.

## Global Constraints

- New fields: `weekdays: Set<Weekday>` on `WaterPrefs` and `MeditationPrefs` (Reading and Gym have it), and `daysOff: Set<DayKey>` on all 4 prefs. Defaults: all 7 weekdays; empty `daysOff`.
- `DayKey` raw format `"YYYY-MM-DD"`, Gregorian, user time zone. It is `Codable` as a plain string.
- `Limits.daysOffMaxAhead = 365`, `Limits.daysOffMax = 100`. `Limits.gymWorkDays` is replaced by `Set(Weekday.allCases)` as the Gym default.
- Follow the `/data-migration` skill, recipe "Add a field". No schema bump. Decode with `DecodingDefaults` helpers (`knownSet(.weekdays, or:, keepsEmpty: false)`; `daysOff` drops unparseable keys and keeps the rest).
- `scheduleKey` includes every buddy's `weekdays` and `daysOff`.
- No code comments. Max 200 lines per file. No magic numbers. Core reads time only from `clock.now`. Every switch on `HabitID` exhaustive, no `default:`, no `id == .water` checks in shared code.
- Tests first. Use `EngineHarness` and `FakeClock`. Test filters match type names (`./scripts/test.sh HabitDaysTests`).
- Ask the user before each commit unless they approve per-task commits on `feature/days-off`. Never push.

## Review Focus

1. A saved `daysOff` with a bad key (`"2026-13-40"`, `42`) loads the other keys and every other setting (Task 2 test `badDayKeysAreDroppedOthersKept`).
2. A DST day and a time-zone change: a date off stays the same calendar date (Task 2 test `dayKeyIsStableAcrossDST`, Task 3 test `offDateOnDSTDay`).
3. Water with every weekday but 1 off and that 1 day also in `daysOff`: the next due time is 1 week later, never `.distantFuture` before 8 days are checked, and never a past date (Task 3 test `onlyDayIsAlsoADateOff`).
4. Turning today off while a reminder shows closes only that buddy's reminder (Task 4 test `todayOffClosesOnlyThatBuddy`).
5. A streak across a month boundary with off days on both sides (Task 5 test `streakSkipsOffDaysAcrossMonths`).

### Task 2: `DayKey`, `HabitDays`, and the prefs fields

**Files:**
- Create: `Sources/SathiCore/Models/DayKey.swift`, `Sources/SathiCore/Habits/HabitDays.swift`
- Modify: the 4 `*Prefs.swift`, `Models/Prefs.swift`, `Constants/Limits.swift`
- Test: `Tests/SathiCoreTests/DayKeyTests.swift`, `HabitDaysTests.swift`, `DaysOffPrefsTests.swift`, `LenientPrefsDecodingTests.swift`; update `GymPrefsTests.swift` for the new Gym default.

**Interfaces (produces):**
- `package struct DayKey: Hashable, Comparable, Codable, Sendable { package let raw: String }`
  - `init?(raw: String)` validates `YYYY-MM-DD` and a real date.
  - `init(_ date: Date, calendar: Calendar)` uses `Calendar.gregorian(in: calendar.timeZone)`.
  - `func start(in calendar: Calendar) -> Date` is the start of that day.
  - Encodes and decodes as a single string. Decoding a bad string throws (the set decoder drops it).
- `package struct HabitDays: Equatable, Sendable { package var weekdays: Set<Weekday>; package var daysOff: Set<DayKey> }`
  - `func isOn(_ date: Date, calendar: Calendar) -> Bool`: the weekday is in `weekdays` (empty counts as all 7) and the day key is not in `daysOff`.
  - `func nextOnDay(onOrAfter date: Date, calendar: Calendar) -> Date?`: start of the first on day in `0 ... Limits.daysOffMaxAhead + Limits.daysPerWeek` days, else `nil`. Changed 2026-10-27 (user): 14 days left a habit with no reminder after a long break, and nothing re-plans at midnight.
  - `func upcoming(from now: Date, calendar: Calendar) -> [DayKey]`: sorted keys on or after today.
- Each prefs struct: `package var weekdays: Set<Weekday> = Set(Weekday.allCases)` (new on Water and Meditation) and `package var daysOff: Set<DayKey> = []`.
- `Prefs.days(_ id: HabitID) -> HabitDays` (exhaustive switch).
- `Limits.daysOffMaxAhead = 365`, `Limits.daysOffMax = 100`. Gym default `weekdays = Set(Weekday.allCases)`. Delete `Limits.gymWorkDays` and fix its users (`GymRules.isWorkDay` uses `HabitDays` in Task 3).
