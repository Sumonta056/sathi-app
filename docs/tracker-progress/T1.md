Key choices:
- The prompt lives in `LiveState.tracker.prompt` (persisted); `trackerRuntime.shownPrompt` says whether the presenter shows it. A held prompt (lock) shows on a later tick.
- Plain A is planned only when nothing runs, inside hours, not busy, at `max(whatNowAt, hours start)`. `whatNowAt` = now + askEvery after Skip of A or Esc (runtime only; after a restart A may ask at once).
- C asks for a running activity also after tracker hours on a tracker day (rule 25), never on a non-tracker day or a day off (G2); it is held by break, time block, session, quiet, Away, and lock.
- User-asked prompts (B, A after Done or after a session, D) skip the hours check.
- Done does not end the activity at once: A opens with the Started row; Start or Skip in A ends the old activity at the picked time (rule 13a).
- Late "Still on it" sets confirmedUntil = now (rule 22, literal).
- Midnight: the activity always ends at min(confirmedUntil, 00:00), so no unconfirmed time is added.
- A pending Done (A open with the Started row) ends the activity at the Done switch-from time on every other path (session, block, tracker off, Away, midnight, Esc, B), and is never offered as Continue.
- No idle check while a buddy session runs; a session end resets the last input time. A lock or sleep during a break keeps the Break cause until the break ends. Start or B during an Away closes the Away with no D. A time block across midnight is saved as 2 items.
- Idle: deadline `lastInput + idleMinutes`; the idle seconds are read only there. While in an idle Away (and no session), each normal tick (max 60 s) reads the idle seconds to see the return (no new timer).
- Break: the activity ends at the break start (rule 10, not the confirmed rule).
- Buddy session inside tracker hours: ends the running activity, saves it in `beforeSession`, starts a `buddy` activity (category added with the buddy color). The end opens A with Continue and the Started row from the session end, on the next tick (the session is still set inside the hook).
- Event hooks of track C are called at: `tickTrackerEvents` before C is planned (event beats C, G65), `trackerEventDeadlines` in deadlines, `savingToCalendar` on end (not for buddy), `calendarActivityEdited`/`Deleted` in the report API and in I was here, `logEventsWhileAway` on return, `unloggedRunningEvent` in A and B state.
